# mkfix/fix — lists and multileg orders

Moved out of `CLAUDE.md` in this directory (40,000-character cap); the rest of the engine is described there.

## Lists: `lists.py` (0.77)

A list is every order of one ListID(66) on a session and side. `fix_lists` (`LIST_COLS`, on the family infrastructure: `_FAMILY_COLS`, `_find_family_row` by `direction`) holds its own row — `mode` (`E`, `D`, `E+D`), BidType(394)/ListExecInstType(433) names and codes, `tot_no_orders` (68), `status` (ListOrderStatus(431) by name, Sent/Received before one), `status_type` (429), the request slot `pending_action` (New/Execute/Cancel), texts, `last_order_at`, `raw_message`. Its orders are `fix_orders` rows with `list_id` and `list_seq_no` (67; written once like the instrument, `_NO_LIST`), numbered by arrival when a message carries no 67. `lists_query` counts them (`orders`, `done_orders`, `pending_orders`, `filled_qty`) and carries them as the New List grid takes them (`list_orders`, JSON; Clone opens on it, an instrument by the saved name matching it), re-run by `watch_columns` on fix_orders.

- **Sending** — `send_new_list(orders, mode, bid_type, exec_inst_type, tot_orders, text, extra_tags, client)`: `orders` is the grid's JSON (or dicts) — New dialog terms, a saved instrument's name as `instrument` (its terms under what the row typed). Each order is built as a NewOrderSingle (instrument, client, list and own extras, `text`) and written, the list row with them, before anything is sent. **E** from 4.2 (`defines("394")`): one NewOrderList, `factory.new_order_list` putting each order's body (`lists.member_pairs`, ClOrdID then 67) in NoOrders(73) in the dictionary's member order; before 4.2, one NewOrderList a member with 66/67/68 in its body. **D**: each order a D with 66 (and 68 when `tot_orders`), no 67. A failed send rejects what did not go out (a list nothing reached is `Failed`).
- **Joining** — a D carrying 66, sent (`send_new_order(list_id=)`, `add_list_order`, or `66=` in the extras) or received (`_handle_new_order`), joins its list through `_join_list`, which makes the row if none (mode D), turns an E list's mode into `E+D`, stamps `last_order_at`, and parks `New` on a received list with nothing pending. A received order of a ListID is its list's whenever it comes; only archiving closes a list. Events `list`/`list joined` (received), `sent list`, and the orders' own.
- **Receiving** — E (`_handle_new_order_list`): the list row (mode E, its terms), then each member through `_handle_new_order` as the D it stands for (`lists.list_members` splits 73 at each ClOrdID, dictionary-free — 5.0SP2's group is ragged; `member_message`). N (`_handle_list_status`): a sent list's status, status type, 444; it clears an Execute answered by 431 Executing/AllDone/Reject and a Cancel by AllDone/Reject or 429 AllDone. Orders keep what their ERs said. L/K (`_handle_list_request`) park in the slot; M (`_handle_list_status_request`) is answered at once from the tables (429 Response, 73 reports: 11/14/39/151/84/6 where defined). An L, K or M naming no list gets a ListStatus Reject "Unknown list".
- **Client actions** — `execute_list` (L), `cancel_list` (K, or — `as_orders`, the default for D — `send_cancel` for each working order), `request_list_status` (M); L and K fill the slot (`_send_list_request`).
- **Market actions** — `accept_list`/`reject_list` answer the slot (or orders pending New): New accepts/rejects each pending order (`accept_order`/`reject_order`) and, for a NewOrderList, sends ListStatus Ack with 431 ReceivedForExecution (433=2) or Executing — or Reject; Execute → ExecStarted/Executing; Cancel → each working order `unsolicited_cancel`, then AllDone. `send_list_status` (unsolicited, Alert by default), `fill_list` (every working order for its leaves at its limit or the given price; none without a price), `cancel_list_orders`. Market ERs for a list's order carry 66 (`_stamp_order`).
- **AllDone** — `_finish_list` (0.80): a list whose every order is finished, and none of its TotNoOrders still to come, is `AllDone` (`lists.all_done_name`; 431=6 in `list_status_code`) on both sides — sent, from the ER that finished the last (whether or not a ListStatus says so, and whether events are listened to; then `list done`); received, from `_write_order` when the market finished its last.
- **UI** — Sent Lists / Received Lists (mkui 1.24's grid in New List…, Clone, Add Order…, Macro…); the list ops have macro verbs since 0.78 (macro/CLAUDE.md). A D's 68 updates the received list's `tot_no_orders`. `tests/test_lists.py`, `TestListBlotters`.

## Multileg orders: `multileg.py` (0.79)

One order over several instruments, sent as NewOrderMultileg (35=AB) and replaced with MultilegOrderCancelReplace (35=AC), legs in NoLegs(555). FIX 4.1 and 4.2 carry the multileg subset of 4.4 (`tools/overlays/FIX4?.multileg.json`: AB/AC, 555 without nested groups, 563, 167=MLEG, and 442 into 4.1; never Parties); `multileg.supports(dictionary)` is where AB is (4.0 refused).
- **Pure part:** `normalize_leg(s)` (grid JSON, dicts, words or codes, C/P), `check_legs` (two or more, own LegRefIDs, positive ratios), `leg_pairs`/`group_pairs` (dictionary member order; Put/Call in 1358 from 5.0 SP1, else a derived LegCFICode 608, which `legs_of` drops again), `legs_of`, `legs_text` (`-1 ES Dec26 / +1 ES Mar27`), `legs_json` (the grid's codes), `strategy_symbol`.
- **Rows:** `fix_order_legs` (`LEG_COLS`; versioned; data group, `created_at`, alias `legs`), keyed by (session, direction, `order_id`, `seq`); `_write_legs` keeps a leg's fills when its place is rewritten, drops legs no longer there. `fix_orders` gains insert-only `legs`, `leg_count`, `multileg_rpt_type` (`_NO_LIST` defaults) and `pending_legs`, moved by `set_order_legs`; `fix_executions.leg_ref_id`; `fix_instruments.legs` (a strategy: `save_instrument(legs=)`, security type MLEG, display the legs text).
- **Send:** `send_new_multileg` (write-before-send, `sent order` with the tag, list_id as `send_new_order`); `send_cancel_replace` on a multileg order sends AC with `legs` or the order's own, parked in `pending_entered["legs"]` and written by `_promote_entered`. Received: AB is `_handle_new_order` (leg tags consumed), AC parks its legs in `pending_legs` until `accept_replace`.
- **Reports:** `_stamp_order` puts 442=3 on every ER of a multileg order; `fill_leg` (market action) sends a leg's report — 442=2, the leg's instrument, side, units and price (LegPrice unless given), `555=1|600|654|637` — moving only the leg's fills and its own trade row (`leg_ref_id`); `fill_multileg` is Fill's `leg`/`report_legs` (actions `fill_order` routes there). Inbound 442=2 goes to `_handle_leg_report` (leg by 654, else symbol; event `fill`/`er` with `detail.leg`, never `filled`). 442 is a consumed exec tag.
- **UI:** New Multileg… (Sent Orders; Strategy pick via `strategies_list`, legs grid, 563, Save strategy as), Replace's legs grid (`orders_query.legs_json`, shown when `leg_count > 0`), Fill's Leg/Report legs, Sent/Received Order Legs (`order_legs_query`, linked from the order blotters by `order_id`), Legs columns (a multileg row tinted by `rowStyle` on `leg_count`, its Legs and MLEG instrument coloured; `TestMultilegRows`), strategy legs in Config › Instruments, template scope `multileg` (`legs`, `rpt_type`). Clone is off for multileg rows. `tests/test_multileg.py`.
