# mkfix/static — the scenario UI

The rest of the UI is described in the root CLAUDE.md. This file covers what scenarios added.

## Rule: the browser knows no word of the language

Everything the editor knows comes from the server: the vocabulary (`fix_cmd scenario_vocab` → `mkfix/scenario/vocab.vocabulary()`) drives colouring, completion and F1 help, and `check_scenario` supplies the problems it underlines. The Python parser alone decides what a script means; colouring that is slightly off can never make a bad script look accepted. Do not list verbs, events or terms in JS — `test_scenario_ui.py::test_every_word_of_the_vocabulary_is_coloured` holds the rules to the vocabulary.

## Files

- `scenario-lang.js` — pure functions, tested under node: `buildRules(vocab)` (one ordered regex list, first match at a position wins), `aceRules(vocab)` (the same without the one lookbehind rule, for Ace), `tokenizeLine`/`highlight` (the Help viewer colours code blocks with the same list), `blockKindAt`, `completionsAt(vocab, lines, row, col, extras)` (headers at the top of the file; verbs and statements valid for the block's side at the start of a line; events after `when`/`wait`/`expect`; a verb's unused terms, trade targets and `using`; enum words after `side:` etc.; template names after `using '`; session names after `run on`; fields after `order.`/`trade.`/`event.`/`event.prev.`; otherwise context names and functions), `helpAt`.
- `panes/scenarios.js` — list + Ace editor. Ace is vendored prebuilt in `vendor/ace` (ace-builds 1.44.0: `ace.js`, `ext-language_tools.js`, `ext-searchbox.js`, `keybinding-vim.js`, `LICENSE`) and loaded as classic scripts on first use; `basePath` lets Ace fetch the vim keybinding itself. Our mode, indentation folding and theme are `ace.define`d at run time; the theme module carries no CSS — `.ace-mkfix` rules live in `mkfix.css` on mkui's variables. `useWorker: false` (there is no worker file). Check runs 300 ms after typing stops, guarded by a sequence number so a late answer to old text is dropped; diagnostics become annotations plus `scn-mark-*` markers. Save is allowed with problems (a draft); Arm needs a saved, clean script and no live run, and reads **Run…** when the check reports a `client` block (the same `arm_scenario` command starts `run on` blocks and arms the rest). Live scripts' lines are marked from `scenario_instances_query` when the text is unedited. vim: `localStorage` `mkfix.scenario.vim`, `:w` = Save. F1 sets `app.state.help_target`; the Runs selection (`selected_scenario_instance`) moves the cursor; `open_example` (set by the Help viewer) opens a copy of a bundled example. Arm… is `app.dialog("arm_scenario", { row: { name } })` — a named dialog in app.json, not modal, like every mkfix dialog.
- `markdown.js` — the renderer for help pages: headings with slug ids, paragraphs, nested lists, fenced code (optional `highlight(code, lang)`), tables with `\|`, rules, inline code/bold/italic/links; HTML is escaped and only `http(s)`, `#…` and relative links survive. `headings(text)` feeds the contents list.
- `panes/help-viewer.js` + `help/index.json` + `help/*.md` — the Help pane. A page is a Markdown file, or `builtin: "examples"`, which is built from `fix_cmd list_examples` (the examples' header comments) with **Open in editor**, and carries **Set up loopback sessions** (`fix_cmd setup_loopback`). Links to `other.md#anchor` navigate inside the pane. The pages are the user documentation and are linked from the README; they must keep to what `markdown.js` renders, their `scenario` code blocks must check clean, and the reference's Actions/Events/context tables must equal the vocabulary — `test_scenario_ui.py::TestHelpPages` enforces all three.
- app.json: panes `scenarios`, `help-viewer`, and three declarative tables `scenario-runs` (Pause/Resume/Stop), `scenario-instances` (Detach; publishes `selected_scenario_instance`), `scenario-log`; dialogs `arm_scenario` and `scenario_keys`; Trading menu entries before Templates (which a test keeps last); Help menu leads with Scenario Language and Scenario Editor Keys; a `scenario` column on both order blotters. `test_every_declared_dialog_is_opened_by_something` accepts a dialog opened by a menu or by a pane's `app.dialog("name"`.
